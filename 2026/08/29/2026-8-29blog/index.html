2026-08-29- 2026-08-30

今天又是在 Codex 里泡了一整天，从早上一直忙到晚上，简单记一下。

量化：tushare 接口到期前的数据大整理

tushare 数据接口快到期了，今天把权限内能下的数据基本都重新下一遍，顺便把整个数据仓库翻新了一遍。

权限普查

  • 抓了 Tushare 文档站全部 264 个文档页（228 个数据接口），用最小调用逐个实测 token 权限
  • 15000 积分覆盖日线/财务/特色数据（限速 500 次/分钟），191 个接口可下载（84%）
  • 32 个无权限：分钟类（stk_mins 等）、实时类、美股日线、新闻/公告/研报/政策、集合竞价、盘前股本、国债收益率曲线等，都是单独付费权限
  • 有趣发现：factor_list（因子列表，2000元/年）没权限，但 factor_value（因子数值）实测居然能下

数据库改名 + 目录重构

  • 把中文路径的「数据库」改名成 quantdb，20 个中文目录按 Tushare 官方 API 名统一改名（映射存在 _rename_map.json，可回退）
  • 统一目录结构：逐日/单表存 /.parquet（或 all.parquet），逐代码存 /by_code//.parquet
  • 同步更新 30 处引用（配置、下载脚本、factor_build、quantlab v2 loader 等），全部编译通过 + 端到端冒烟测试

全量下载

  • 写了通用下载器 download_tushare_all.py（–tier/–start-year/–resume），带限速、重试、增量续传
  • 踩坑 1：后台 session 被回收中断 → 改成独立后台进程 + 日志文件，断点续传
  • 踩坑 2：fund_share 日期列写错（end_date 实际是 trade_date）导致崩溃，修掉重下成功
  • 踩坑 3：stk_weekly_monthly 参数用错（应该按 trade_date+freq 每周/月末拉全市场，不是按代码拉历史）
  • 踩坑 4：续传「5 天阈值」对周线/财务报表不成立（最新报告期本就滞后）→ 改成「已有 parquet 即跳过」，大幅提速
  • 最终 185 个数据集目录 / 137 GB

数据质量审计（今天最折腾的部分）

  • 扫描 144 万个 parquet 文件：0 个空文件，清掉 7533 个空目录
  • 回填 1064 个缺失交易日（adj_factor 缺 08-25/26、fut_daily 缺 390 天等，都是批量下载时 API 瞬时错误被静默跳过）
  • 发现「部分交易日」幻觉数据：adj_factor 有 6 个半截日（482 行 vs 正常 5516 行）、fut_daily 36 个、fx_daily 89 个等
  • 又踩坑：并行修复时并发写同一个 year 文件导致竞态，22 个文件损坏 → 改成串行 + 重建损坏文件
  • 最终覆盖度：核心日频数据全部到 2026-08-28（最近交易日）✓

派生数据 + 搬家

  • daily_hfq（后复权日线）/ market_daily（当日行情）/ industry_daily（每日行业）都更新到 08-28
  • dynamic_adj（动态复权）原来停在 2026-04-24，重算到 20260828 快照（后复权+前复权，2004-2026 共 23 年全量）
  • 动态复权.py 原来按 *_bfq.parquet 命名找数据（和现结构不符）→ 适配成 *.parquet，并新增非交互驱动 regenerate_dynamic_adj.py
  • quantdb 挪到 F 盘根目录（F:/Quant_in_A_Share/quantdb → F:/quantdb，137GB 同盘秒级移动），同步更新 30 处引用
  • 最终质量确认：843 个顶层文件完整读取，0 损坏、0 空文件，核心数据到 08-28（fx_daily 08-27 是外汇滞后一天，正常）

没下成的（权限原因）

  • stk_mins 分钟数据（2000元/年）→ 本地停在 06-12，没法批量更新
  • hk_daily 港股日线（1000元/年）→ 限流 1 次/分钟
  • factor_value：Tushare 1000 次/天硬限制，今天额度已用尽；173 因子 × 402 天 ≈ 7 万次请求，要跑 70 天 → 跳过并写进 README
  • fut_index_daily 南华指数代码格式没确认 → 跳过

交付物：F:/quantdb + 数据字典 quantdb_registry.json / quantdb_README.md（接口名/中文名/存储模式/下载方法/规模/最新日期/权限/速度/质量），以及 backfill_gaps.py、download_missing.py、download_final.py 等工具。

B站监控

  • 给「与君疏」的监控程序整合成一个 bat 放在桌面，抢首评默认关闭
  • 每 10 秒轮询一次，今天跑的时候被 B站风控临时限了 IP（-352），脚本自动退避 60 秒重试，问题不大
  • 之后有新视频/动态就会在电脑上弹条幅提醒
