小说写作项目：从 skill 到微调

本来想训练一个 skill 来写漂亮句子/写小说，结果搞清楚了：Codex 的 skill 本质是「说明书 + 参考资料包」，不是训练出来的，也不需要本地大模型。对比了 skill 和蒸馏/微调的区别后，还是决定走蒸馏路线，搞一个自己的模型。

F:/life/novel 项目

  • DeepSeek 小说专用 API 配好（generate_chapter.py –model api 打通，key 已写进 gitignore）
  • 拉取本地模型 qwen2.5:14b（Ollama，9.0GB），实测生成正常，速度约 10-20 token/s

语料准备

  • 番茄目录里 8 本完本网文 + 5 本名著（epub），抽出 12,393 章 / 约 2943 万字（网文 2675 万 + 名著 268 万）

AI 审查调研

  • 调研了最新的 AI 审查/检测手段，找到公开的「网文 AI 味量化检测库」（12 项指标）
  • 落地成自检扫描器：真人网文 0.0/10，AI 生成 3.0/10（比喻密度 11.2/千字、对白占比 0%、环境堆砌）

微调：本地训练撞墙 → 装 WSL2 解决

  • 环境：LLaMA-Factory 0.9.5 + 基座 Qwen2.5-7B-Instruct（15GB，hf-mirror 太慢改走 ModelScope 下载）
  • 踩坑一串：pip 把 torch 偷偷换成了 CPU 版、torchaudio 版本不匹配、LLaMA-Factory 0.9.5 必须显式写 do_train: true（否则静默退出不训练）
  • 最大的坑：Windows 上训练循环卡在第 0 步——GPU 100% 但功耗只有 47-49W/165W（典型的等 CPU 派发 kernel），试遍 4-bit QLoRA / fp16 LoRA、torch cu124/cu128、各种 batch/序列长度/梯度检查点、torch.compile（Windows 上直接编译失败），全部无效
  • 排查出换 cu128 运行时前向从 4.3s 降到 0.74s（6 倍加速），但训练仍然卡死 → 结论是 Windows + 4060 Ti（WDDM 驱动）+ transformers 训练栈的兼容性问题
  • 解决办法：装 WSL2。DISM 启用 WSL + VirtualMachinePlatform，重启后装 Ubuntu 22.04，在 WSL 里重新搭 CUDA/Python/LLaMA-Factory 跑训练

训练成功 + 写作流水线

  • Qwen2.5-7B 4-bit QLoRA，5000 对话对，loss 1.96，合并模型；Ollama 挂 novel-writer（LoRA adapter q8_0）+ qwen2.5:7b + 14b
  • 流水线：books.json 多书管理（novels/<书名>/bible/outline/chapters/state/db.sqlite）、memory_db.py 关系图谱（人物/事件/关系/共现 Jaccard）、generate_chapter.py –model api|ft|local|novel-writer –ai-check、plan_book.py 总纲规划

实际写了一本书：《不小心捡到魔道小公主该怎么办》

  • 写了 10 章（1500-2560 字/章），AI 味自检 2-3 分，关系库 23 人 / 68 事件 / 51 关系
  • 修了内容跳跃（重排 10 章渐进弧：戒备→发烧破冰→开口说话→俏皮帮倒忙→乖灵果→父王伏笔）、岁岁的人设、章节衔接
  • 找到章节不连贯的根因：API 前情没喂上一章结尾 → 现在自动接上一章末尾 400 字，章与章真正衔接
  • 凌晨还在讨论：怎么让 AI 懂「合理性」（四层夹逼：写作铁律+场景约束+bible 硬规则+合理性审查关卡）、每章标题写死进总纲、上下文管理的最新方案（ConWriter 场景=状态转移+双轨检查）——决定先做 123 不重写

量化数据补漏收尾

  • 继续盯美股财务/周月线下载，发现更早的缺口：1990-12-19 就有数据（之前只补到 1995），回填 1990-1994 共 9504 个交易日
  • 发现批量下载时被限流漏掉了大量交易日：stk_factor 981 天、moneyflow_ths 531、block_trade 255、sw_daily 243，总共约 6800 天 → 重写补漏脚本重拉
  • 踩坑：检查脚本把缺失日列表截断成前 6 个，导致只补了一小部分，重写后完整重算重拉
  • fut_weekly_detail 是误报（日期列是 week_date 不是 trade_date）；2026-08-31 今天数据未发布，正常

量化因子库整理

  • 因子注册表 5815 → 4743（去掉 1072 行别名），数据列 5754 → 4682（物理删除重复列后重建），加 owner 列：woyo 0000001-0004682 + jky 0004683-0004743，61 个 CUSTOM 因子归 jky 并加 _jky 后缀
  • 给全部 4743 个因子生成中文「含义」列（4 种来源：公式内嵌中文 754 / DL 组合递归解析 344 / 手工字典 ~60 / CUSTOM 模式表 61），现在看因子 = 名字（结构）+ 含义（经济意义）
  • 讨论 AI 挖因子：4682 列数量绰绰有余，但 95% 是价格量衍生、4 变体互相复制冗余高——关键是数据源多样性 + 低冗余 + 独立信号源
