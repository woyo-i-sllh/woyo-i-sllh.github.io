============================================================
 我的歌（日语歌 + 华语歌 + 纯音乐 + CD原声）— 使用说明 & 技术复现手册
 根目录：F:\life\songs
============================================================

【一、这是什么】
把喜欢的歌做成「歌词卡 + 本地播放器」：
  · 日语歌：左日文（汉字上方标平假名注音）/ 右中文翻译，逐行对应；
  · 华语歌：纯歌词（不做翻译和注音）；
  · 纯音乐：无歌词，只保留链接与音频；
  · CD原声：直接播放原版 WAV，不压缩、不转码，音质优先；
  · 本地播放器：可听 MP3/WAV、看 MP4，支持切版本、记音量、记上次播放版本；
  · 纯 HTML/CSS/少量 JS + 一个零依赖本地服务，断网可用。

【二、目录结构】（重要：所有脚本都按这个结构找文件）
  F:\life\songs\
    ├─ 日语歌\                     ← 日语歌词卡（每首一个 .html + index.html + 说明.txt）
    │    └─ _tools\
    │         ├─ lyric_data.py      ★ 日语歌数据源（歌名/歌词/注音/翻译）
    │         ├─ lyric_build.py     构建器：校验注音 → 生成 html/index/说明.txt
    │         └─ 说明_template.txt  说明.txt 的模板（改这里，别直接改说明.txt）
    ├─ 华语歌\                     ← 华语歌词卡（每首 .html + index.html）
    ├─ media\<歌名>\                ← 下载好的 mp4 + mp3（日语/华语/纯音乐共用）
    ├─ CD\<专辑名>\                 ← CD原声 WAV（每个子目录一张专辑）
    ├─ app\
    │    ├─ server.py              播放器服务端（四分类：日语/华语/纯音乐/CD原声）
    │    └─ player.html            播放器界面
    ├─ tools\                      各类工具脚本（见第六节）
    ├─ data\
    │    ├─ songs.db               日语歌数据库（歌名/链接/媒体）
    │    ├─ cpop.db                华语歌数据库
    │    ├─ instrumental.db        纯音乐数据库
    │    ├─ cd.db                  CD原声数据库（WAV 媒体）
    │    └─ cd_album_meta.json     CD 专辑→歌手元数据映射
    └─ logs\                       运行日志、pid 文件

【三、页面功能】
  · 「隐藏假名」：藏起汉字上方的假名，用来自己回忆读音；
  · 「隐藏翻译」：只看日文，练听力/阅读；
  · 「打印」：可打印或另存为 PDF；
  · 「🔗 找歌链接」：显示这首歌的所有链接（数据库里的，所有人可见）；
  · 「＋ 添加链接」：直接在页面上粘贴链接入库（严格绑定当前页，同名歌不串）。

【四、播放器（本地听歌/看 MV）】
  · 启动：双击桌面「启动听歌.bat」，或 python F:\life\songs\tools\start_server.py
  · 地址：http://127.0.0.1:8787/   （顶部可切 日语歌 / 华语歌 / 纯音乐 / CD原声）
  · 停止：桌面「停止听歌.bat」，或 python F:\life\songs\tools\stop_server.py
  · 功能：
      - 左边歌单（可搜索），右边播放区 + 歌词联动；
      - 听歌(mp3) / 看MV(mp4) 一键切换；
      - 「版本」下拉：同一首歌的不同版本（原曲 / 高桥李依翻唱 / 合集分P 等），
        显示原视频标题；默认优先人工添加的版本，并记住上次选择；
      - 音量全局统一（任意一个视频里调音量，所有视频都生效）；
      - 「复制下载命令」：复制该版本的下载命令；
      - 链接区：显示/添加链接（数据库里的链接需用 linkdb 删除）。

【五、标准流程（以后加歌都按这个来）】

◆ 日语歌：加一首新歌
  1) 【日文歌词 + 注音】以日本歌词站为准，优先级：
        UtaTen（うたてん，优先；通常同时提供日文原文和官方ふりがな）
        → 歌ネット（uta-net，最权威但常限流）
        → 官方 MV / 官方发行页 → 萌娘百科日文页（带 ruby）→ j-lyric。
        UtaTen 页面若显示“歌詞掲載に向けて準備中”，说明官方歌词尚未公开，不得用自动分词或猜测歌词替代。
     注音要求：汉字按词连缀整体标注；带送假名只标汉字部分；
     特殊读法（能力=チカラ、標的=やつ、運命=さだめ 等）必须按官方标注。
     歌词正文严禁写「漢字(かな)」或「漢字（かな）」；所有读音必须放 notes，由构建器生成上方 ruby。
     如果来源本身用括号注音，先运行 tools\convert_inline_furigana.py 迁移；括号属于和声、重复句、
     强调词而不是读音时保留，不能为了清括号误删歌词。
     没有可靠官方注音源时，由 Codex 根据完整句意、人物称呼和歌曲语境逐句人工注音；
     禁止直接把 pykakasi、UniDic、Sudachi 等自动注音结果写入正式歌词。
     上述分词器只可作为找疑点的排查工具，不能生成或覆盖正式读音。
     「君」必须按上下文区分：代词/直接称呼“你”读 きみ；人名后敬称“某某君”读 くん。
     歌词正文第一行必须是真正可唱的第一句。演唱、歌手、乐团、作词、作曲、编曲、录音、
     混音、母带、监制、助理、出品、原声吉他、电吉他、人声、编程、贝斯、小提琴、中提琴、大提琴、萨克斯、小号、长号、键盘、弦乐、词曲、OP/ED 来源行、Studio/Producer/Engineer 等制作人员或平台元数据禁止写入
     sections；这些信息只能放 credit。来源歌词若带头部/尾部名单，必须先清理再建卡。
     歌手字段只写歌手或团体正式名，禁止包含歌名、版本名、链接标题或站点标签。
     歌名翻译已停用：title_cn 必须留空，歌词卡和播放器都不再显示中文歌名或“中文名 · 歌手”。
     title_jp 末尾的 ~since 2007~、~grace edition~、~Acoustic Version~ 等仅表示版本，必须去掉；
     若波浪号内容属于歌名本身（如 secret base～君がくれたもの～），则保留。
     subtitle_cn 只放真正的歌曲介绍；credit 只放作词/作曲/发行/作品出处等版权信息。
     “我的歌单”“B站合集”“日推歌曲”等合集/歌单占位文字禁止出现在歌手、title_cn、
     subtitle_cn 或 credit 中。
  2) 【中文翻译】由 AI（Codex）直接翻译，意译即可、看懂就行，不照抄网络译本。
  3) 【写卡片】把 (日文, 注音, 中文) 写进 日语歌\_tools\lyric_data.py，然后
        python F:\life\songs\tools\normalize_jp_metadata.py
        python F:\life\songs\tools\dedupe_jp_songs.py          # 先预览重复组
        python F:\life\songs\tools\dedupe_jp_songs.py --apply  # 确认后合并重复版本
        cd F:\life\songs\日语歌\_tools
        python lyric_build.py        # 校验注音 + 生成 html/index/说明.txt
     normalizer 会清理混入正文的制作人员行，并剥掉歌词行开头残留的 LRC 时间戳；builder 若再发现这类行会直接停止，防止错卡上线。
     典型制作人员行包括“原声吉他/电吉他/人声/编程/贝斯/小提琴/萨克斯/键盘/混音/母带/词曲/CAST/OP・ED 来源”等。
     误判风险较高的 OP/ED 规则必须限制为明确来源格式，不能只因英文词尾出现“ED”就删除。
     dedupe 会把重复入口的链接和 MP4/MP3 迁到保留歌曲，不丢版本。
     同名歌曲禁止只按歌名合并。合并前必须比较日文歌词正文：
       · 歌名相同且日文歌词归一化后相似度 ≥ 0.98，才可视为同曲/翻唱并合并版本；
       · 歌词不同的同名歌曲必须保留，例如《ありがとう》的不同作品、不同歌手的同名异曲；
       · 合并时优先保留媒体和链接更完整、非占位、带正式歌词的页面；
       · 合并后检查链接、MP4、MP3 和歌单引用全部迁到保留页。
     歌曲介绍（subtitle_cn）可持续分批补。优先从已保存的 B站说明提取明确来源：
        python F:\life\songs\tools\fill_jp_intros_from_bili.py          # 预览
        python F:\life\songs\tools\fill_jp_intros_from_bili.py --apply  # B站说明来源
        python F:\life\songs\tools\fill_jp_intros_from_netease.py --apply  # 网易云ID→专辑/年份
        python F:\life\songs\tools\fill_jp_intros_from_netease_search.py --apply  # 歌名+歌手搜索补缺
        python F:\life\songs\tools\fill_jp_intros_fallback.py                 # 最后只写“由X演唱”
     没有可靠来源时禁止编造影视、动画、专辑或游戏出处；最低只能写歌手事实。
     标题和歌词读音以可靠官方来源为第一优先级。没有官方源时由 Codex 按上下文人工注音；
     不允许自动注音工具直接写库。历史数据修正可运行：
        python F:\life\songs\tools\convert_inline_furigana.py --apply
        tools\venv\Scripts\python.exe tools\repair_jp_furigana.py   # 仅用于遗留数据修复
  4) 【加链接】播放器里选中这首歌 → 粘贴 B站链接 → 添加；或
        python F:\life\songs\tools\linkdb.py add "歌名" "名称" "https://…" --kind mv
  5) 【下载】python F:\life\songs\tools\download.py fetch --all
        （只下没下过的；单首 --song "歌名"，指定链接 --link-id N）
  6) 【发布】日语歌词站：运行 F:\life\hexo\woyoblog\sync_jpop.ps1

◆ 日语歌：加 B站合集 / 演唱会 Live
  A) 普通分P合集
     · 用分P接口列出全部曲目：https://api.bilibili.com/x/player/pagelist?bvid=<BV号>；
     · 已有歌 → 给那首歌追加版本；新歌 → 建立正式条目、歌词卡、歌手歌单和链接。

  B) UGC合集 / season / 演唱会
     · 从 view 接口读取 `ugc_season.sections[*].episodes`，不要只看当前BV的 pages；
     · 先过滤实际现场表演，排除 Reaction、翻弹、猜歌、朗读、教程、混剪；
     · 一个视频包含多首歌曲时，同一链接分别挂到每个对应歌曲下；
     · 已有歌曲只追加 live 版本，保留原 MV 和旧版本，不覆盖、不替换；
     · 缺少歌曲页时补建正式条目，并加入对应歌手歌单；
     · 纯音乐只建“纯音乐 · 无歌词”卡，不进入翻译/注音校验。

  C) 新歌歌词必须同步补齐
     · 日文原文/官方 ruby：UtaTen → 歌ネット → 官方发行渠道 → 网易云 → Codex 人工处理；
     · 中文翻译和注音可使用本机 DeepSeek skill：
       C:\Users\woyo4\.codex\skills\deepseek-japanese-lyrics\SKILL.md
       默认模型 `deepseek-flash`；只有用户明确同意才使用 `deepseek-v4-pro`；
     · 写库后依次运行：
       python F:\life\songs\tools\split_furigana_surfaces.py --apply
       python F:\life\songs\tools\audit_furigana.py
       python F:\life\songs\日语歌\_tools\lyric_build.py
     · 新建歌曲不得以“歌词整理中”直接发布；只有用户明确要求暂缓歌词时才允许占位。

  D) 下载与发布
     · 人工选定/用户提供的批次，note 统一写成 `user:<批次标签>`（例如 `user:batch:aimyon_master:BV1qfRxBgEM1`），播放器会优先人工版本；`download.py --tag <批次标签>` 仍可按 note 子串匹配。
     · 自动筛选批次可使用 `live:season:<id>` 等其他标签：
       python F:\life\songs\tools\download.py fetch --tag live:season:<id>
     · 校验 MP4/MP3 数量、大小、时长和重复项；
     · 最后运行 sync_jpop.ps1，将歌词卡、链接和新歌一起发布。

◆ CD原声：新增一张专辑 / WAV
  1) 把 WAV 按专辑分目录放好，例如：
       F:\life\songs\CD\だから僕は音楽を辞めた\01 - 8-31.wav
       飞牛对应目录：N:\CD\だから僕は音楽を辞めた\01 - 8-31.wav
     推荐文件名格式：两位以上音轨号 + " - " + 日文曲名；文件内部无标签也可正确建档。
     自动抓轨（实体 Audio CD）：
       · 光驱盘符可用 Get-CimInstance Win32_CDROMDrive 检查；H: 为常见盘符。
       · 工具：tools\rip_audio_cd.py，读取 libdiscid 的 TOC/ISRC，再调用系统 ffmpeg 的 libcdio 输入抓成 PCM WAV。
       · 例：python F:\life\songs\tools\rip_audio_cd.py --drive H: --album "AIMYON BEST ALBUM - 唇を追え！ -" --disc 1 --tracklist F:\life\songs\data\cd_rip_AIMYON_BEST_DISC1.json
       · MusicBrainz ISRC 查询用于识别专辑和曲名；ISRC 重复或光驱偶发返回错误时必须用人工核对后的 tracklist JSON，不能盲信。
       · USB 光驱读到碟尾可能重试或迟迟不结束；前 N-1 轨可保留，末轨单独用 -ss/-t 抓取并比较两次 SHA256，稳定后将 RIFF/data size 修正为合法偶数 PCM 边界，再用 ffmpeg 解码验收。
       · 抓轨后必须运行 build_cd_db.py，确认 WAV 时长和曲序，再同步 N:\CD 与 N:\data\cd.db。
       · 当前 NAS 若因旧容器未重建而让 /media/cd/... 返回 404，可运行 tools\publish_cd_to_media.py：
         把 CD\ 镜像到 media\_cd\（本机优先硬链接，不额外占空间），并把 cd.db 的 path 改到 media 卷；
         这样无需重建容器即可播放 WAV，CD\ 仍保留为母版。正式重建并挂载 CD volume 后，重新运行 build_cd_db.py 即可切回 CD\。
  2) 在 data\cd_album_meta.json 登记专辑名与歌手；目录名会自动忽略首尾及全角空格：
       "だから僕は音楽を辞めた": {"artist": "ヨルシカ", "artist_cn": ""}
     未登记的专辑会把专辑目录名临时当作歌手，随后应补登记。
  3) 重建 CD 数据库（脚本会用 ffprobe 读取时长）：
       python F:\life\songs\tools\build_cd_db.py --source F:\life\songs\CD --db F:\life\songs\data\cd.db
  4) 本机验证：启动播放器，切到「💿 CD原声」，确认曲序、歌手、WAV 时长和播放正常。
  5) 同步 NAS：运行 tools\upload_to_nas.ps1 -Destination N:\；脚本会同步 cd.db、CD\ 和四个分类需要的部署文件。
  6) CD原声始终使用 WAV 原文件，不生成 MP3、不转码；服务端以 /api/songs?lang=cd 返回曲库。

◆ 本机 → NAS：更新方式必须区分
  A) 只改了以下数据：database、CD\WAV、media、歌词卡/html/歌单/JPG 等静态资源
     · 运行 upload_to_nas.ps1；
     · 飞牛容器无需重启；浏览器刷新即可；PWA 若仍显示旧页面，升级 sw.js 缓存版本后重新打开。
  B) 改了 app\server.py
     · 上传后必须在飞牛 Docker Compose 中重启/重新部署 songs 项目，让 Python 进程重新加载服务端。
     · 普通刷新页面不会加载新 server.py。
     · 重启后必须做媒体冒烟测试：jp / zh / inst 的 URL 应为 /media/<相对路径>，CD 应为 /media/cd/<相对路径>；
       各取一首带媒体歌曲发送 Range: bytes=0-1023，正确结果必须为 HTTP 206。
     · 若出现 /media/media/... 双重前缀，说明 media_relative_path 拼接错误；不得发布，先修 server.py 再重启。
  C) 改了 docker-compose.yml、Dockerfile 或新增/删除 volume
     · 数据文件若在已有 volume（如 cd.db 位于 data\）中，普通重启即可让曲库和入口出现；
     · 但新增的 volume 不会随普通重启可靠挂入容器。2026-09-29 实测：普通重启后 CD
       曲库可见，但 /media/cd/... 返回 404，说明 WAV 目录没有挂载；
     · 新增或修改 volume 后，标准做法是执行“重新部署 / 重建并启动”，而不是只做普通重启。
  D) 改了 app\player.html 或 app\sw.js
     · 静态文件会从映射目录读取；仍需刷新浏览器；
     · 改页面缓存策略或 PWA 外壳时必须同步升级 sw.js 中的 CACHE 版本。


【五·补、卡片"长相"规范（每次写卡片必须遵守）】
  ◆ 字体（可爱体）
     · 卡片界面文字统一用 **ZCOOL KuaiLe（站酷快乐体）**，兜底 幼圆/YouYuan；
       构建器（lyric_build.py）已内置该字体与 Google Fonts 引用，**本地和线上都生效**，
       不再依赖 Hexo 的 inject_jpop.js（那个只是早期补丁）。
     · 歌词正文（.jp）保留明朝体/宋体系（Yu Mincho / MS Mincho / Noto Serif JP），
       保证日文汉字与假名的可读性；翻译（.cn）用黑体系。
  ◆ 分段
     · 当前已按用户要求取消所有 HTML 分段：歌词按数据顺序连续排列；
     · lyric_build.py 不再输出 part-label / stanza；
     · 不要运行 resegment.py，也不要重新添加“开场/副歌/第一段”等标题。

【六、工具一览】

【七、技术实现细节】

(1) 左右两栏逐行对齐
  · 每行是一个 <div class="row">，内含 .jp（日文）与 .cn（中文）；
  · .row{display:grid;grid-template-columns:1.08fr 1fr;column-gap:36px;}

(2) 假名 = HTML <ruby>：<ruby>漢字<rt>かな</rt></ruby>
  · CSS：.jp ruby{ruby-position:over;ruby-align:distribute-space}
  · 「隐藏假名」= body 加 no-rt 类 → body.no-rt ruby rt{display:none}

(3) 构建器（lyric_build.py）
  · 先硬校验歌词正文：发现演唱/歌手/作词/作曲/录音/混音/Studio/Producer 等元数据立即停止；
  · 校验每行汉字的注音覆盖是否完整、与 pykakasi 的差异（差异需人工判断）；
  · 生成每首歌 html + index.html；
  · 用 说明_template.txt 生成 说明.txt。

(4) 数据库（data\songs.db / data\cpop.db / data\instrumental.db / data\cd.db）
  · songs 表：歌名/歌手/专辑；links 表：链接（主键=页面文件名，唯一约束 (song_file,url)）；
  · media 表：下载结果（kind、path、size、duration、video_id、title、来源 url）；
  · 构建时把 links 写进 HTML 的 window.__linksInit → 链接随网页同步到所有设备。

(5) 播放器服务端（app\server.py，Python 标准库，零依赖）
  · GET /api/songs?lang=jp|zh|inst|cd；GET /media/<相对路径>（支持 Range，可拖进度条）；
  · CD 使用 /media/cd/<相对路径> 映射，只读挂载 CD\；WAV 同样支持拖动进度条。
  · GET /lyrics/<lang>/<页面名>（iframe 联动）；POST /api/link（绑定当前页加链接）。

(6) 下载（yt-dlp + ffmpeg）
  · 空间投稿页使用“真实 Edge 页面 + CDP DOM 抓取”而非直接请求 WBI API；直接 API 会遇到 -352/412。
    工具会把不同分页的视频标题、BV 号和页面原始标题落盘，后续导入器再做过滤和查重。
  · 优先 H.264(avc1)+AAC（兼容性好）；先下 mp4，再抽 320k mp3；
  · 绿色版工具在 tools\bin、tools\venv，不动系统。

【八、常见问题】
  · uta-net 403：被限流，等恢复或改用 UtaTen/萌娘；恢复后用于交叉核对。
  · B站搜索 412：需要 cookies；脚本自动读 tools\cookies.txt 或 F:\life\songs\cookies.txt。
  · B站空间/合集列表 412（如 space.bilibili.com 上传页）：优先使用不读取用户 cookies 的 CDP 页面方法：
      1) 启动带 --remote-debugging-port=9223、--remote-allow-origins=* 和正常浏览器 UA 的 Edge；
      2) 打开 space.bilibili.com/<mid>/upload/video；
      3) 等待页面出现“TA的视频”卡片；
      4) 运行 tools\fetch_bilibili_space_cdp.py --mid <mid> --out data\<name>.json --port 9223。
    若页面仍要求验证，再才需要含 SESSDATA 的 cookies.txt；不要把用户 cookies 写入仓库或日志。
  · cookies 不生效：多数插件不含 HttpOnly 的 SESSDATA；用「Get cookies.txt LOCALLY」
    重新导出，或完全退出 Edge 后用 --cookies-from-browser edge；bili_check.py 可体检。
  · 控制台乱码：脚本统一 UTF-8；bat 用 UTF-8(无BOM) + chcp 65001。
  · 播放器连不上：重启用桌面「启动听歌.bat」。
  · NAS 已上传 CD/WAV 但播放器仍没有 CD原声：先看 /api/songs?lang=cd 是否返回曲库；
    如果曲库有 14 首但 /media/cd/... 为 404，说明 CD volume 未挂入，必须重新部署/重建容器。
  · 能选歌、能收藏，但点播放没反应：先查 API 媒体 URL 是否出现 /media/media/... 双前缀；
    四个分类的媒体 Range 请求都应为 HTTP 206。此问题只需修正 media_relative_path 并重启 server.py。
